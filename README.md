### How tracking works

- **GitHub Issues** are actionable deliverables. Close an issue only when its acceptance criteria are met and evidence links are added.
- **TRACKER.md** is the durable overview; update it in a weekly review.
- **Journal entries** record what changed your understanding, implementation and measurements.
- **Monthly architecture reviews** update the skill matrix using evidence, not self-confidence alone.
- Avoid uploading employer code, production logs, customer data, private runbooks, or confidential architecture details. Build with synthetic/public/authorized data.
